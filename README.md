UART_rx (приемник байт с пк )

Слушает линию rx (в покое на ней 1). Падение линии в 0 — начало старт-бита.
 Приёмник отсчитывает такты до СЕРЕДИНЫ каждого бита и читает линию там,
   где сигнал уже устоялся: старт-бит, 8 бит данных (младший первым), стоп-бит.
 КУДА ОТДАЁТ ДАННЫЕ
   rx_data   — принятый байт;
   rx_valid  — импульс 1 такт: "в rx_data новый байт". Байт забирает очередь
               byte_fifo (см. 09_robot_top/robot_top.sv);
   frame_err — импульс 1 такт: стоп-бит оказался 0 (не та скорость, помеха,
               обрыв). Такой байт НЕ выдаётся.
   1) rx проходит через два триггера (синхронизатор): линия приходит с ПК,
     она не связана с нашим clk, и без синхронизатора возможна метастабильность.
   2) В середине старт-бита линия проверяется ещё раз: если там уже 1, это была
      короткая помеха, а не старт-бит, — возвращаемся в ожидание.
   3) После ошибки кадра ждём, пока линия вернётся в 1 (WAIT_IDLE), иначе
      "залипшая" в 0 линия давала бы поток ложных байт.

ОТКУДА БЕРЁТ И КУДА ОТДАЁТ
   Запись:  wr_valid + wr_data  <- uart_rx (rx_valid + rx_data).
          У приёмника нельзя попросить "подожди", поэтому если очередь полна,
           байт теряется и поднимается флаг overflow (горит до сброса).
   Чтение:  rd_valid + rd_data -> cmd_parser, rd_ready <- cmd_parser.
          Это рукопожатие valid/ready (см. ниже).
РУКОПОЖАТИЕ VALID/READY — так в проекте связаны все модули
 valid = 1: "у меня есть данные, они лежат на шине data"
  ready = 1: "я готов их забрать"
 Передача происходит на том фронте clk, где valid = 1 И ready = 1.
  Пока ready = 0, отправитель держит valid и data без изменений.
 КАК УСТРОЕНА
 Память mem[] на DEPTH байт (Quartus положит её в блок памяти M9K) и два
  указателя: wr_ptr — куда писать, rd_ptr — откуда читать. Указатели на 1 бит
  шире адреса: так "пусто" (указатели равны) отличается от "полно"
  (отличаются ровно на DEPTH). Байт из памяти заранее переносится в выходной
  регистр rd_data, поэтому парсер видит его сразу, без лишнего такта.
